OSCAL library — Getter / Setter Coverage

One table per OSCAL model, organized by information topic. Each row groups a related set of getters with their matching setters (same row, separate columns) and names the relevant OSCAL JSON location(s). Implemented and planned members are shown together. By the library convention, every single-object getter (e.g. control) has a matching setter; plural/collection getters (e.g. controls) do not — their topic row instead carries the collection-level mutators (append / insert / create).

Status implemented planned Scope Common · all models Shared · listed models Model-specific

The Common · all models block below is inherited from the base OSCAL class and is identical in every model; it is repeated in each table for convenience. Planned assessment getters are drawn from docs/assessment_getters.md (all of §3–§5, including the .get_*_by_uuid() resolvers). Implemented so far on the assessment layer: the intra-document getters (.observation() / .risk() / .finding(), each keyed by uuid); the POA&M .poam_tree attribute; and the local-definition .components() / .component() / .inventory_items() / .inventory_item() getters on all three assessment models (these traverse the import chain to the SSP by default — local_only=True restricts to the document; the singular getters take include_all=True for an additional-versions array; every returned object carries a provenance = {uuid, href, imported} of its source document, and an SSP-owned component bubbles up in its full .component() shape). Also implemented: .user() / .users() and .assessment_platform() / .assessment_platforms() (cross-chain, with the platform injecting a components[] array); and cross-reference injection on .finding() / .risk() / .observation() (cited observations/risks inlined with a cycle guard; observation subjects + evidence resolved; every origins[].actors[] populated via .actor()). This document is kept current as getters and setters land.
